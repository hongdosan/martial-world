> 본 명세된 행위가 **Phase 3 도메인 모델링 사이클** 의 직접 입력이 된다 (행위 → 도메인).

## 2. 액터 정의

| 액터 | 정의 | 인증 상태 |
|---|---|---|
| **Visitor** | 비로그인 방문자 | ❌ |
| **사용자** | 로그인한 일반 사용자 (커스텀 강호 소유 가능) | ✅ |
| **운영자** | 천기망 운영자 (홍혁준) — 베이스 데이터 편집 권한 | ✅ + 운영자 권한 |

> ※ *사용자 ⊃ Visitor* — 사용자는 Visitor 의 모든 행위 가능 + 추가 행위.
> ※ *운영자 ⊃ 사용자* — 운영자는 사용자의 모든 행위 가능 + 추가 행위.

## 3. 기능 요구사항 (FR)

### 3.1 베이스 사전 조회 (읽기 + 검색)

**FR-3.1.1** Visitor 는 베이스 강호 데이터의 *영역별 목록* 을 조회할 수 있다.
- 영역: 캐릭터 / 무공 / 문파 / 경지 / 기연 / 칭호 / 기타

**FR-3.1.2** Visitor 는 베이스 강호 데이터의 *항목 상세* 를 조회할 수 있다.

**FR-3.1.3** Visitor 는 베이스 강호 데이터를 *키워드로 검색* 할 수 있다.

**FR-3.1.4** Visitor 는 검색 결과를 *영역별로 필터링* 할 수 있다.

**FR-3.1.5** Visitor 는 항목 간 *관계* 를 따라 탐색할 수 있다.
- 예: 캐릭터 → 배운 무공 → 소속 문파

### 3.2 사용자 인증

**FR-3.2.1** Visitor 는 *회원가입* 할 수 있다.
> ※ 인증 방식 (이메일 / OAuth / Magic Link) = vision.md §6 Deferred — Phase 1 plan 단계 결정.

**FR-3.2.2** Visitor 는 *로그인* 할 수 있다.

**FR-3.2.3** 사용자는 *로그아웃* 할 수 있다.

**FR-3.2.4** 사용자는 자기 *프로필 (표시명 / 이메일)* 을 조회할 수 있다.

**FR-3.2.5** 사용자는 자기 *프로필을 수정* 할 수 있다 (표시명).

**FR-3.2.6** 운영자는 *운영자 권한으로 식별* 된다 (사용자 ↔ 운영자 권한 분리).

### 3.3 커스텀 강호 편집

> ※ 커스텀 강호 = vision.md §4.1 *CustomWorldview BC*. 사용자가 베이스를 분기한 자기만의 강호.

**FR-3.3.1** 사용자는 베이스를 *분기하여 새 커스텀 강호를 생성* 할 수 있다.

**FR-3.3.2** 사용자는 *여러 커스텀 강호를 보유* 할 수 있다 (1 사용자 → N 커스텀).

**FR-3.3.3** 사용자는 자기 *커스텀 강호 목록* 을 조회할 수 있다.

**FR-3.3.4** 사용자는 *활성 커스텀 강호를 전환* 할 수 있다.

**FR-3.3.5** 사용자는 자기 커스텀 강호의 *항목을 추가* 할 수 있다 (캐릭터 / 무공 / 문파 / ...).

**FR-3.3.6** 사용자는 자기 커스텀 강호의 *항목을 수정* 할 수 있다.

**FR-3.3.7** 사용자는 자기 커스텀 강호의 *항목을 삭제* 할 수 있다.

**FR-3.3.8** 사용자는 자기 커스텀 강호의 *특정 항목을 베이스 기본값으로 복원* 할 수 있다.

**FR-3.3.9** 사용자는 자기 커스텀 강호 *전체를 베이스 기본값으로 복원* 할 수 있다.

**FR-3.3.10** 사용자는 자기 커스텀 강호를 *삭제* 할 수 있다.

> ※ 베이스 데이터는 *불변* — 사용자 편집 시도 시 *자동으로 자기 커스텀으로 분기* (vision.md §4.1.1).

### 3.4 커스텀 가져오기 / 내보내기

**FR-3.4.1** 사용자는 자기 커스텀 강호를 *파일로 내보낼* 수 있다.
> ※ 파일 형식 = vision.md §6 Deferred — JSON 우선 권장. MD / CSV / SQL 후속 검토.

**FR-3.4.2** 사용자는 *외부 파일을 가져와 자기 커스텀 강호로 적용* 할 수 있다.

**FR-3.4.3** 사용자는 가져오기 시 *적용 방식을 선택* 할 수 있다.
- 옵션 1: 현재 활성 커스텀에 *덮어쓰기*
- 옵션 2: *신규 커스텀 강호 생성*
> ※ *병합 / 충돌 해결* 은 비범위 (Phase 1 MVP 이후).

### 3.5 베이스 수정 의견 (사용자 → 운영자 채널)

**FR-3.5.1** 사용자는 베이스 항목에 대한 *수정 의견을 운영자에게 제출* 할 수 있다.

**FR-3.5.2** 사용자는 자기 *의견 제출 이력* 을 조회할 수 있다.

**FR-3.5.3** 운영자는 *받은 의견 목록* 을 조회할 수 있다.

**FR-3.5.4** 운영자는 *받은 의견 상세* 를 조회할 수 있다.

> ※ 의견 처리 워크플로우 (승인 / 반려 / 반영) = Phase 1 MVP 비범위. 운영자가 *직접 베이스 편집* 으로 반영하는 형태.

### 3.6 커뮤니티 게시판

> ※ 간단 블로그 형식 (사용자 명시) — 게시글 단방향. 댓글 / 좋아요 = Phase 1 MVP 비범위.

**FR-3.6.1** Visitor 는 *게시글 목록* 을 조회할 수 있다.

**FR-3.6.2** Visitor 는 *게시글 상세* 를 조회할 수 있다.

**FR-3.6.3** Visitor 는 *게시글에 첨부된 커스텀 파일을 다운로드* 할 수 있다.

**FR-3.6.4** 사용자는 *게시글을 작성* 할 수 있다.

**FR-3.6.5** 사용자는 *게시글에 자기 커스텀 강호 파일을 첨부* 할 수 있다.

**FR-3.6.6** 사용자는 자기 게시글을 *수정* 할 수 있다.

**FR-3.6.7** 사용자는 자기 게시글을 *삭제* 할 수 있다.

**FR-3.6.8** 사용자는 게시글 첨부 파일을 *다운로드 후 자기 커스텀 강호로 가져오기* 할 수 있다.
> ※ FR-3.4.2 와 동일한 가져오기 행위 — 게시글이 진입점일 뿐.

### 3.7 운영자 베이스 관리

**FR-3.7.1** 운영자는 *베이스 항목을 추가* 할 수 있다 (캐릭터 / 무공 / 문파 / ...).

**FR-3.7.2** 운영자는 *베이스 항목을 수정* 할 수 있다.

**FR-3.7.3** 운영자는 *베이스 항목을 삭제* 할 수 있다.

**FR-3.7.4** 운영자는 *항목 간 관계를 설정* 할 수 있다 (예: 캐릭터 ↔ 무공 ↔ 문파).

> ※ *변경 사항 일괄 발행 (publish) / 버전 관리* = Phase 1 MVP 비범위. 운영자 편집 = *즉시 반영* 형태.

> 1인 사이드 프로젝트 + MVP 1차 — 보수적 / 간소.

| NFR-2 | **가용성** | 단일 서버 / 다운타임 허용 | 1인 운영 — SLA 없음 |
| NFR-3 | **보안 — 인증** | 편집 / 의견 / 게시판 = 인증 필수 | Visitor = 읽기만 |
| NFR-4 | **보안 — 권한** | 운영자 ↔ 사용자 권한 분리 | 베이스 편집 = 운영자 only |
| NFR-5 | **보안 — 데이터** | 사용자 커스텀 = 본인만 접근 (타 사용자 노출 금지) | 공유는 *수동 내보내기* 만 |
| NFR-6 | **접근성** | 웹 + 모바일 반응형 | vision.md §4.4 (PWA 출발) |
| NFR-7 | **데이터 영속성** | 사용자 데이터 (커스텀) = 서버 저장 / 디바이스 무관 | vision.md §4.1.4 갱신 |
| NFR-8 | **언어** | 한국어 only | 다국어 = 후속 |
| NFR-9 | **백업** | 운영자 베이스 데이터 백업 정책 (수동 또는 주기적) | 메커니즘 후속 |
